# GitHub完整目录同步

2026-10-20用户最新约定：Git/GitHub同步和GitHub Pages发布均由用户手动执行。助手完成本地修改与必要核验后，不自动暂存、提交、推送、调用本说明中的同步脚本或发布Pages，也不反复询问是否执行。只有用户另行明确委托某次操作时才执行该次操作。下述命令及双击入口保留供用户手动使用；同步范围与账户隐私要求继续有效。主分支同步与Pages发布仍为两个独立操作。

目标：本地项目与 `oooo0h/Investment` 的 `main` 分支保持相同的正式文件路径和字节内容。唯一项目目录排除项为根目录“临时文件”；Git自身的“.git”是本地版本库元数据，不属于待上传项目内容。

用户于2026-10-20明确得知仓库公开后，单独确认允许账户原文件公开上传。正式交易记录、净值表、PDF、网站源码与正式本地来源说明均纳入同步；对话、终端、日志仍不显示账户金额，凭据不得上传。

共享依赖入口现在位于 `临时文件/node_modules/`；网站构建产物位于 `临时文件/fund-trade-web/dist/`。两者不属于正式文件树。空的“定时任务”目录按用户要求保留为空，Git不记录空目录。

使用Codex提供的Python运行时执行：

```text
python 工具脚本/github_mirror.py prepare
python 工具脚本/github_mirror.py apply
python 工具脚本/github_mirror.py verify
```

`prepare` 只读扫描全部正式文件、压缩文件内的凭据模式、云端完整文件树和已有暂存状态，生成 `临时文件/GitHub完整同步/plan.json`。清单明确列出全部文件的路径、大小、SHA-256、Git对象哈希、变化与云端旧路径删除范围，不包含文件内容或账户金额。

`apply` 复读文件和远端状态，只暂存刚审查的清单及已经发生的删除，逐项核对暂存树与正式目录相同，然后正常提交和推送，不强推、不额外删除本地文件。存在用户暂存、远端变化、分叉、冲突、凭据模式或审查后文件变化时停止，不覆盖。

`verify` 重新读取本地和GitHub完整文件树，核对路径集合、每个文件的Git对象哈希、两端提交及临时文件排除。全部相同才输出成功，结果只保存在临时目录。只做新增上传的旧清单流程不再使用。

本机原生Git HTTPS连接目前受网络限制；`apply` 使用 `github_api_transport.py` 调用GitHub官方Git数据库API传输相同的本地提交。复用已存在对象，分批写入目录树，核对完整树和提交哈希与本地完全相同，最后以 `force=false` 更新main。不会新造不同的提交、强推或绕过并发核验。同步成功后更新本地远端缓存；凭据由既有GitHub CLI授权提供，不打印、不写入脚本。

项目中的更新、移动和删除都在同一个仓库提交中反映。该主分支同步与网站Pages发布是两个操作，不把完整项目作为公开站点目录部署。

## 双击入口

在项目根目录双击 `一键同步本地文件到GitHub.cmd` 即可运行。公共逻辑位于 `工具脚本/github_sync.py`，复用上述完整镜像与逐项哈希核验，不改变同步范围。支持新增、修改、重命名和本地已有删除；不强推、不自动合并远端变化，不删除本地资料。同步目标固定为 `oooo0h/Investment` 的 `main`，不会将整个项目发布成网站。

窗口按4步显示：检查环境 → 扫描本地与云端 → 正常提交并上传 → 核验目录及内容。耗时操作每10秒显示仍在执行；仅在核验通过后显示“同步成功”。没有变化也会核验，不创建空提交。任务结束保留窗口，按任意键关闭。重复双击时只有一个窗口执行，锁随进程退出释放。

日志保存在 `临时文件/GitHub完整同步/sync-*.log`，只记录步骤、计数和结果，不输出文件正文、账户金额、令牌或原始异常。清单与Git API临时进度也保存在该目录，不上传。入口优先使用本机已有Codex Python运行时，再回退到PATH中的Python；Git与GitHub CLI需要已经安装，CLI需已登录并有仓库写权限。

仅核验不提交、不上传：

```powershell
.\一键同步本地文件到GitHub.cmd --check
```

自动检查时可设置 `GITHUB_SYNC_NO_PAUSE=1`，或将 `--no-pause` 作为第一个参数，跳过结束暂停。检查模式显示两步并明确说明“检查完成，未上传”。

上传中断后重新双击可继续上次完整核验过的单个本地提交：只接受原云端父提交未变、正式文件和已提交文件树仍与原清单完全一致的情况。如果中断后本地又改动、远端并发更新或有其他未推送提交，则停止并保留全部修改，先核对版本。未审查的暂存、凭据模式、错误分支、路径或内容变化均会停止，不显示成功。
