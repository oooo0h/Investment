# GitHub完整目录同步

目标：本地项目与 `oooo0h/Investment` 的 `main` 分支保持相同的正式文件路径和字节内容。唯一项目目录排除项为根目录“临时文件”；Git自身的“.git”是本地版本库元数据，不属于待上传项目内容。

用户于2026-10-20明确得知仓库公开后，单独确认允许账户原文件公开上传。正式交易记录、净值表、PDF、网站源码与正式本地来源说明均纳入同步；对话、终端、日志仍不显示账户金额，凭据不得上传。

共享依赖入口现在位于 `临时文件/node_modules/`；网站构建产物位于 `临时文件/fund-trade-web/dist/`。两者不属于正式文件树。空的“定时任务”目录按用户要求保留为空，Git不记录空目录。

使用Codex提供的Python运行时执行：

```text
python 工具脚本/github_mirror.py prepare
python 工具脚本/github_mirror.py apply
python 工具脚本/github_mirror.py verify
```

`prepare` 只读扫描全部正式文件、压缩文件内的凭据模式、云端完整文件树和已有暂存状态，生成 `临时文件/GitHub完整同步/plan.json`。清单明确列出全部文件的路径、大小、SHA-256、Git对象哈希、变化与云端旧路径删除范围，不包含文件内容或账户金额。

`apply` 复读文件和远端状态，只暂存刚审查的清单及已经发生的删除，逐项核对暂存树与正式目录相同，然后正常提交和推送，不强推、不额外删除本地文件。存在用户暂存、远端变化、分叉、冲突、凭据模式或审查后文件变化时停止，不覆盖。

`verify` 重新读取本地和GitHub完整文件树，核对路径集合、每个文件的Git对象哈希、两端提交及临时文件排除。全部相同才输出成功，结果只保存在临时目录。只做新增上传的旧清单流程不再使用。

项目中的更新、移动和删除都在同一个仓库提交中反映。该主分支同步与网站Pages发布是两个操作，不把完整项目作为公开站点目录部署。
