# GitHub完整目录同步

2026-10-20用户最新约定：Git/GitHub同步和GitHub Pages发布均由用户手动执行。助手完成本地修改与必要核验后，不自动暂存、提交、推送、调用本说明中的同步脚本或发布Pages，也不反复询问是否执行。只有用户另行明确委托某次操作时才执行该次操作。下述命令及双击入口保留供用户手动使用；同步范围与账户隐私要求继续有效。主分支同步与Pages发布仍为两个独立操作。

目标：本地项目与 `oooo0h/Investment` 的 `main` 分支保持相同的正式文件路径和字节内容。唯一项目目录排除项为根目录“临时文件”；Git自身的“.git”是本地版本库元数据，不属于待上传项目内容。

用户于2026-10-20明确得知仓库公开后，单独确认允许账户原文件公开上传。正式交易记录、净值表、PDF、网站源码与正式本地来源说明均纳入同步；对话、终端、日志仍不显示账户金额，凭据不得上传。

共享依赖入口现在位于 `临时文件/node_modules/`；网站构建产物位于 `临时文件/fund-trade-web/dist/`。两者不属于正式文件树。空的“定时任务”目录按用户要求保留为空，Git不记录空目录。

使用Codex提供的Python运行时执行：

```text
python 工具脚本/github_mirror.py prepare
python 工具脚本/github_mirror.py apply
python 工具脚本/github_mirror.py verify
```

`prepare` 只读扫描全部正式文件、压缩文件内的凭据模式、云端完整文件树和已有暂存状态，生成 `临时文件/GitHub完整同步/plan.json`。清单明确列出全部文件的路径、大小、SHA-256、Git对象哈希、变化与云端旧路径删除范围，不包含文件内容或账户金额。

`apply` 复读文件和远端状态，只暂存刚审查的清单及已经发生的删除，逐项核对暂存树与正式目录相同，然后正常提交和推送，不强推、不额外删除本地文件。存在用户暂存、远端变化、分叉、冲突、凭据模式或审查后文件变化时停止，不覆盖。

`verify` 重新读取本地和GitHub完整文件树，核对路径集合、每个文件的Git对象哈希、两端提交及临时文件排除。全部相同才输出成功，结果只保存在临时目录。只做新增上传的旧清单流程不再使用。

同步入口已改用标准 Git HTTPS 推送：在本次进程中沿用系统代理、使用 HTTP/1.1，并通过现有 GitHub CLI 登录提供凭据。暂存等步骤若因部分克隆而按需下载 Git 对象，也沿用同一登录，无需额外配置 Git 凭据。推送前重新核对工作文件、已提交文件树、远端父版本及本地历史；正常推送，不强推。推送后仍通过 GitHub API 核对完整文件树、每个文件哈希和提交，全部一致才显示成功并更新本地远端缓存。`github_api_transport.py` 是旧的分批目录树传输实现，主入口不再调用。

项目中的更新、移动和删除都在同一个仓库提交中反映。该主分支同步与网站Pages发布是两个操作，不把完整项目作为公开站点目录部署。

## 双击入口

在项目根目录双击 `一键同步本地文件到GitHub.cmd` 即可运行。公共逻辑位于 `工具脚本/github_sync.py`，复用上述完整镜像与逐项哈希核验，不改变同步范围。支持新增、修改、重命名和本地已有删除；不强推、不自动合并远端变化，不删除本地资料。同步目标固定为 `oooo0h/Investment` 的 `main`，不会将整个项目发布成网站。

窗口按4步显示：检查环境 → 扫描本地与云端 → 正常提交并上传 → 核验目录及内容。耗时操作每10秒显示仍在执行；仅在核验通过后显示“同步成功”。没有变化也会核验，不创建空提交。任务结束保留窗口，按任意键关闭。重复双击时只有一个窗口执行，锁随进程退出释放。

日志保存在 `临时文件/GitHub完整同步/sync-*.log`，只记录步骤、计数和结果，不输出文件正文、账户金额、令牌或原始异常。清单与Git API临时进度也保存在该目录，不上传。入口优先使用本机已有Codex Python运行时，再回退到PATH中的Python；Git与GitHub CLI需要已经安装，登录账户需有仓库写权限。

手动启动时先检查 GitHub 当前授权。未登录或令牌失效会调用 GitHub CLI 的浏览器登录流程，原窗口保持等待；授权成功并重新核验后自动继续同次同步，无需再次双击。登录取消或未完成时，可按回车重试，输入 Q 结束。一次性验证码仅显示在 GitHub CLI 的交互窗口，不进入同步日志。登录期间遇到网络故障会明确提示网络问题，不要求重复登录；无效的 `GH_TOKEN` / `GITHUB_TOKEN` 环境变量需先清除或更新，脚本不会擅自修改。

若上传过程中授权失效，会引导登录并重新执行原有目录、提交和远端父版本核验，最多自动恢复一次；版本冲突或核验不一致仍停止。

Git 命令只返回笼统错误时，会再次核验授权；只有确认登录失效才引导重新登录。网络、权限、远端冲突和忽略规则错误分别提示，不显示原始异常或凭据。网站 `local/` 下的配对状态文件属于正式项目文件，随完整目录同步，不应被子目录忽略规则排除。

暂存中断时，已暂存内容保留。下次运行先对照上次清单和原本地提交，确认每项暂存变化都属于已审查文件，再重新审查当前工作文件并继续；新清单记录已核验的暂存快照。出现清单之外的暂存字节、冲突、暂存快照变化或不匹配的本地提交时仍停止，不清空暂存区。远端版本继续在准备、提交和上传前核对。

手动同步发现 `.git` 缺失时，会在“临时文件”中从固定 GitHub 仓库克隆 `main` 的版本库元数据，不检出文件。核对云端分支、提交、索引和本地全部正式文件哈希后，只将 `.git` 装回项目，再继续同步。不会重建独立历史、覆盖现有项目文件或重置已有版本库；恢复过程中远端或本地文件变化会停止。恢复记录留在 `临时文件/GitHub完整同步/repository-recovery-*/result.json`。`--check` 只核验，不触发版本库恢复。

命令行未单独配置代理时，会仅在当前进程中沿用 Windows 系统代理，供 Git 和 GitHub CLI 使用；已有代理环境变量优先。代理地址及凭据不写入项目或日志，TLS 校验保持启用。

仅核验不提交、不上传：

```powershell
.\一键同步本地文件到GitHub.cmd --check
```

自动检查时可设置 `GITHUB_SYNC_NO_PAUSE=1`，或将 `--no-pause` 作为第一个参数，跳过结束暂停。检查模式显示两步并明确说明“检查完成，未上传”。

无人值守的检查可额外传入 `--non-interactive`，禁用浏览器登录和输入等待；未登录时给出明确原因并退出。`--no-pause` 仅控制结束暂停，不禁用手动登录。

上传中断后重新双击会保留已有本地提交。工作文件未变化时继续上传已核验提交；有新的本地修改时，只有确认原远端版本未变、已有本地提交确实属于上次已审查历史，才重新扫描当前文件并生成新清单。新增修改正常追加提交，不覆盖或修改原提交。非本入口已审查的未推送提交、远端并发变化、分叉、未审查暂存、凭据模式或新一轮核验后的文件变化，均停止并保留修改。`--check` 可完成重新审查，但不提交或上传。
