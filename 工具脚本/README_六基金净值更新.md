# 六基金历史净值日常核验

范围：270023、005698、016701、006373、006485、006663。仅维护公开净值，不读取账户、交易或组合状态，不修改调度或Git。

2026-10-20存放规则：各基金根目录直接放置 `<代码>_全部历史净值.xlsx` 一份完整表格，不建立“历史净值”文件夹，不恢复JSON、CSV、最近两年表或按截至日期命名的副本。机器JSON/CSV及公开响应集中放在 `公共资料/历史净值/维护数据/<代码>/`。基金根目录的交易记录继续保留，单笔交易自动计算双模式模板及债基交易账本已按用户要求删除，后续不得恢复。PDF定期报告按报告所属年份归入 `PDF报告/<年份>/`，其他文件按版本或公告年份归档。

先读项目规则、对应任务文本、全基金和六基金当前入口。按代码跨持仓基金和观察基金分组定位唯一基金根目录，路径及哈希以全基金入口为准，不使用历史核验报告重建旧路径。

1. `update_five_nav_incremental.mjs --as-of=执行日期` 核验005698、006373、016701、006485、006663的既有东方财富来源。`update_270023_official_nav_incremental.mjs --as-of=执行日期` 核验广发官网主档。均只查询近期窗口及实际缺口，将完整历史候选、响应和证据存入中央维护区。270023的第三方待复核记录与官方主序列保持隔离。
2. 无变化时不重写主档或Excel。有候选时先检查代码、来源、完整历史覆盖、日期唯一性、缺值和修订。保留来源证据及研究冻结输入，复读当前路径和哈希，防止并行覆盖。候选不算已发布。
3. 遵循表格技能使用bundled依赖。中央CSV维持“日期、净值、日增长率”三列、UTF-8 BOM和来源小数精度，JSON保留累计净值、来源和缺值。修订证据与旧冻结版本保存在公共资料，不回写基金目录。
4. 校验后发布固定名称中央JSON/CSV，并在同次工作中同步基金根目录的唯一Excel。`export_single_nav_workbook.mjs --codes=六位代码` 从当前入口指定JSON导出Excel并重导入逐行核验。`compact_nav_formats.mjs --codes=六位代码 --stage` 可暂存中央CSV和基金根目录Excel，再用 `--publish` 发布；候选发布时须按实际情况适配入口元数据及并发检查，不跳过路径和旧文件哈希检查。
5. `organize_single_nav.py --refresh` 逐行核对全部中央JSON/CSV与根目录Excel，检查没有“历史净值”子目录或重复表格，并刷新全基金、四基金和六基金当前索引。`organize_nav_history.py --index` 兼容转发此流程，旧清理模式已停用。
6. `summarize_six_nav_update.py --date 执行日期 --five 五基金结果JSON路径 --official 广发结果JSON路径` 核对已发布主档、唯一Excel及来源证据，生成当日摘要。最终结果须使用真实发布路径和哈希，未导出候选、过期Excel不能通过，不伪造核验完成状态。

执行日期、净值归属日与抓取时间分开。源缺字段保持空白，不按自然日补造净值，不把同源接口当成官网独立核验。历史证据旧路径通过 `公共资料/历史净值/目录迁移记录_2026-10-20.json` 定位；字节哈希不变。供用户阅读的入口只链接Excel。
