# 四基金历史净值日常更新

范围为270023、005698、016701、006373，仅处理公开净值，不读取账户金额、交易或截图。2026-10-19起优先执行项目规则中的目录精简要求。

> 同日另建了面向 005698、006373、006485、006663、016701、270023 的双击一键更新工具，见 [README_双击净值更新.md](README_双击净值更新.md)。其中 270023 使用官网窗口增量并保留第三方待复核记录隔离；本文的 Node 官网核验流程继续保留，可作逐页核验参考。

当前全部基金的唯一主档入口为 `公共资料/历史净值/全基金历史净值当前入口.json`；四基金入口已同步固定路径。旧日期清单和旧核验报告仅作历史记录，其中已移除的路径不得用于重建旧文件。

1. 每只基金只维护 `<代码>_全部历史净值.json/.csv`，已有Excel则同名 `.xlsx` 也只维护一份。新日期合并入完整主序列，不另存按日期命名的历史版本、近两年文件、分页子目录或增量文件。
2. `update_three_nav_incremental.mjs --as-of=执行日期` 读取当前全基金入口，处理三只第三方主档。官网270023的窗口工具已迁至 `公共资料/工具/update_270023_official_nav_incremental.mjs`，需用 `--input` 指定当前官方JSON。官网主序列与第三方待复核补充记录分开保存。
3. 工具生成的新候选、请求响应和核验结果放在 `公共资料/工具/tmp/净值请求/`，不放基金目录。候选必须完成CSV/Excel导出、逐行读回、来源及重复日期/缺值/首末日检查，才能替换同名当前主档。没有变化就不重复生成数据文件。
4. `compact_nav_formats.mjs` 与 `export_public_nav_csv.mjs` 按用户最新要求导出三列：日期、净值、日增长率。日增长率按百分比显示，缺值保持空白；JSON中的累计净值和来源信息继续保留。运行前按表格技能准备bundled依赖和操作标记。不得把只有近期窗口的候选当成全历史，不能省略已有Excel的同步更新。
5. 发布前复读当前主档路径和哈希，避免覆盖并行更新；校验通过后原子替换完整文件。修订旧日期时在同一JSON的修订记录中保留旧值、新值和来源，不另堆版本。
6. 完成同名替换后，运行 `organize_nav_history.py --index`，逐行核对已安装的JSON/CSV并更新全基金和四基金当前入口。基金目录只保留历史净值与定期报告，不再建立scripts、交易分析、研究或临时资料。

旧 `summarize_four_nav_update.py` 和按日期归档的旧工具保留作历史逻辑参考，不可原样发布候选路径为当前主档，也不可用它们恢复旧存储规则。需要执行时先适配范围、来源、哈希及固定文件名。

合并逻辑可用bundled Node运行 `--test 公共资料/工具/tests/nav-incremental.test.mjs` 核验。存量目录整理使用 `organize_nav_history.py` 准备、`compact_nav_formats.mjs` 导出、`organize_nav_history.py --check-staged` 校验后，再由 `apply_nav_cleanup.ps1` 替换；只有用户明确要求清理辅助目录时才使用其 `-RemoveAuxiliary` 参数。旧公开资料移至公共工具tmp内的恢复目录，不再依赖回收站接口。用户交易表格、账本、已填写模板及原始交易资料必须保留，不能纳入清理；历史净值的文件数量限制不适用于这些业务文件。
