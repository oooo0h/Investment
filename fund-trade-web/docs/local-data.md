# 本地网站数据

双击本目录的 `启动网站.cmd`，或在本目录运行 `npm start`，访问 `http://127.0.0.1:4186/`。只监听本机，不启动云端发布。访问密码与原网站一致；金额和份额在解锁后默认隐藏。

页面继续只提供原来的四只基金：016701 银华、006373 国富、270023 广发、005698 华夏。目录内其他基金不会自动加入导航或数据接口。

## 净值

以 `local/nav-index.json` 定位四只基金的 `<代码>_全部历史净值.json`（净值主档仍在各基金目录）。`local/` 由 `npm run sync:local` 从工作区镜像生成，`npm start` 启动时也会自动刷新；网站运行只读 `local/`，不再直接读 `公共资料/`。CSV、Excel只展示日期、净值、日增长率三列，保留与JSON相同的完整主序列；JSON继续保存来源、累计净值等信息。网站直接读取JSON，图表保留时段切换；来源、全历史范围和核验时间等底部说明已按用户要求隐藏。

270023只把官网主序列用于净值曲线；第三方待官网复核的补充记录仍独立保存在主档，不混入曲线。公开数值的原始精度保留在主档与接口的 `navRaw` 字段中。

## 交易

只读取各基金根目录的 `<代码>_交易记录.xlsx`，工作表为“交易记录”，六列顺序固定：交易日期、成交净值、确认份额、交易类型、金额、手续费（元）。每只基金只保留固定名称的完整交易表；带截至日期的旧表在有效交易覆盖核验后归档至根目录临时文件，不作为回退输入。

数字列中的公式读取Excel已保存的计算结果，不执行任意Excel公式；没有结果或公式出错时保留空白并标为待补全。公式计算值保留估算状态，不当作重新核验的成交。对于确认份额列严格同一行的 `=E行/B行`（含绝对引用和空格），若已保存有效计算结果且有手续费，则按六列约定的现金口径在内存重估份额：买入为 `(金额-手续费)/净值`，卖出为 `(到账+手续费)/净值`，保留六位小数并注明公式估算。未改写原工作簿；手填确认份额、其他公式、跨行引用及缺失/错误缓存均不自动改写或补算。读取过程不改写工作簿。数据读取失败与密码错误分别提示，避免将表格问题误报为密码错误。

四只基金现均有六列表。005698、270023 保留原表全部历史记录，并补入旧网站中较新的卖出记录；016701、006373 从旧网站加密备份恢复。合计264条已成交/历史估算记录。006373另有3条旧待确认订单仍在加密备份中，不列入已成交表。

交易日期是下单日期；净值确认日期未提供，网站不把下单日标作成交净值日期。图表优先使用来源备份中的净值日期；仅有下单日期时，在该日已有公开净值的前提下绘制虚边下单标记，并明确说明其非成交净值。休市且没有公开净值的下单日不插值、不顺延、不伪造净值节点。下单日期仍不作为加仓提醒依据。缺少的成交净值、份额、费用保留空白；记录保留展示，但不计入持仓、收益。任何记录资料不完整时，整只基金的账户汇总暂停展示，避免把局部记录当作完整持仓。

逐笔来源状态由本地整理元数据 `local/ledger-metadata.json` 提供，通过工作簿校验和绑定行号。找不到来源标识或工作簿发生变化时，保守视为估算。六列表没有确认状态列，不能仅凭填满单元格声称重新核实了历史成交。来源冲突保留原表数据并暂停相关汇总，不重复添加同一订单。

## 统一数据目录

网站运行时需要的非表格文件都放在 `fund-trade-web/local/`：`discipline.md`（纪律文字）、`nav-index.json`（净值入口）、`ledger-metadata.json` 与 `bond-metadata.json`（来源元数据）。该目录由 `scripts/sync-local.mjs` 从 `交易纪律.md` 和 `公共资料/` 镜像生成，已加入 `.gitignore`。基金净值主档与交易工作簿仍留在各基金目录，按用户要求不搬动。

## 保存与刷新

原始工作簿仅以只读方式打开。网站运行时只读六列表，私有交易通过子进程管道读取到内存，再用原网站的密钥封装加密传给浏览器；不生成明文 JSON、诊断表或账户日志。既有加密文件保留原样，网站运行时仅用于保留原密钥，不自动把旧交易覆盖到表格上。

此次整理前的005698、270023六列表已按原字节备份在公共工具的本地临时目录中；五份更早的原始工作簿均未改动。旧网站恢复的下单日与原表有一处差异：经其他五列逐笔匹配确认后沿用原表下单日，不新增重复记录。未输出任何账户金额的明文中间文件或预览。

页面约每五秒检查已保存文件的变化。更新主档或六列交易表后，无需另外导出网站数据；不合法的文件会中止本次更新，不以测试数据替代。新增基金需要单独明确修改网站范围。

## 净值图交互

电脑端（宽度至少761px）第一次点击固定A点，随后鼠标移动实时显示B点相对A点的净值涨跌幅；再次点击清空，之后可重新选点。区间栏左侧显示自然日天数及日期区间，右侧显示涨跌幅，不显示清除按钮或固定区间提示。鼠标所在点下方显示日期，左右两侧分别在与图表边界的中间位置显示相距天数。左右方向键定位日期，回车选点或清空，Escape清除。只有实际公开净值或明确标识的估值参与比较，待更新日期不生成涨跌幅；曲线数据或所选范围改变时重置选点。

电脑端首次打开时，各主要板块和两只债基卡片默认展开，仍可手动收起；逐笔交易详情保留点击展开。

Y轴按当前可见净值自动确定上下限，刻度数值与视觉间距均等分。成本不在刻度范围内时显示方向提示，交易点超出刻度时显示边缘标记，不为这些参考值压扁净值曲线。“最近上涨”和“最近下跌”合并为一个按钮，依据最新转折自动显示对应走势；无可用走势时禁用。

已补全发布校验模块和Windows发布入口；完整复现步骤见[开发文档](../项目开发与复现说明.md)。2026-10-20按用户要求同步GitHub，原始交易表的公开上传另经二次确认；定时任务未变更。

页面份额统一显示两位小数，计算和原表精度不变。基本信息展示占总持仓的比例（含自由现金流）；美股含量低于40%的基金显示总持仓10%上限及是否超限，已在上限以内时不因该条加仓。

债基纪律按包含自由现金流的总持仓自动核验：1/6和1/3边界均达标，或债基总持仓严格大于纪律规定的固定门槛也达标。两个条件都不满足时，首页第3条显示“比例偏低”或“比例偏高”，展开可查看四舍五入的当前占比、越过的边界及替代条件未满足的原因，并可跳转债基合计；桌面和手机导航同步标记，悬停提示同一原因。债基页显示对应提示并可返回首页规则。资料不足或现金流记录不可用时显示“待核验”，不当作违规；保存或清空现金流、更新净值和表格后立即重算。提示不显示账户金额。

## 估值日期与手机图表

估值输入默认指向北京时间最近一个已结束的工作日，周六、周日不接收手工估值，也不会进入估值链和账户估值。旧版保存的周末估值在读取时过滤，不改写正式净值主档；正式来源的特殊日期记录原样保留。工作日选择不代表完整交易所休市日历，休市日应留空并沿用最新已公布净值。

买入标记为蓝色实心圆，卖出为空心圆；只有下单日期的标记使用虚边，并有文字图例。手机端缩小X轴边界日期、当前查看日期及两侧自然日天数，保留桌面字号。

手机端（宽度不超过760px）只查看单点净值和日期；点击、触摸和键盘均不建立A/B区间，不显示区间涨跌幅栏及选点标记。桌面缩窄到手机宽度时清空旧选点。

交易日期列支持工作簿日期体系下的Excel日期序号（即便被设为常规格式）。新增草稿不会使整个数据接口失败；日期晚于最新公开净值且已有金额、尚缺净值或份额的订单显示为进行中，不计账并保留已确认记录汇总。历史缺失、错误缓存和真实金额不匹配仍须补全或修正。
