# 本地晚间净值轮询

2026-10-20按用户要求实现，入口为 `scripts/serve.mjs` 的真实数据模式。它是本地服务内部的计时器，不依赖应用自动化；演示模式和GitHub Pages均不启动它。2026-10-22另加 Windows 计划任务 `基金账本-晚间净值自动更新`（见下），用于本地服务未运行时的晚间兜底。

- 北京时间19:00前启动时，等待当晚19:00；19:00后启动时立即检查。未达标基金每3分钟重试，不重叠执行更新。
- 非QDII目标为当天交易日，QDII目标为当天之前的最近一个交易日。周末及休市日回退到有效交易日。已达标基金不反复更新，全部达标后停止当晚轮询，等待次日19:00。
- 如当晚尚未完成，跨午夜继续核对原晚间目标；到下一晚19:00切换到新目标。来源暂未发布净值或请求失败都不会被标为已完成。
- 更新复用 `工具脚本/nav_update.py --fund-dir`：逐只更新七只持仓基金，保留全历史、来源及精度，原子替换JSON/CSV/Excel并核对当前入口，不改用户交易工作簿。日志仍在根目录 `临时文件/净值更新/`。
- 本地服务运行期间优先读取公共净值当前入口，避免启动时的 `local/nav-index.json` 副本与更新后的主档不一致。浏览器通过已有版本刷新机制读取更新后的加密持仓快照。
- 关闭浏览器不会停止后台服务；停止本地服务后，内部轮询停止。此时由 Windows 计划任务 `基金账本-晚间净值自动更新` 在每天 20:00、21:30、23:00 兜底：检测到本地网站服务未运行，就调用 `一键更新持仓基金净值.cmd` 直接更新公开净值；检测到服务 live/ready 则跳过，由内部轮询继续。
- Windows 任务使用 `StartWhenAvailable`，睡眠/关机错过触发后在恢复时补跑；包装脚本有命名互斥量，更新器另有文件锁，和内部轮询并发时不会同时改写主档。任务不启动浏览器、不提交 Git、不发布 Pages、不读取账户金额；日志在 `临时文件/净值更新/晚间自动更新.log`。安装/重装脚本为 `工具脚本/安装晚间净值自动更新任务.ps1`，手动只读检查为 `工具脚本/晚间净值自动更新.ps1 -CheckOnly`。

交易日历使用[上交所2026年休市安排](https://www.sse.com.cn/disclosure/dealinstruc/closed/c/c_20251222_10802510.shtml)。当前日历覆盖2026年，跨年需补充已公布的新年度休市安排；遇到未覆盖的日历年份会保留未完成状态，不将普通工作日猜测为交易日，也不误报“已最新”。

## 同次页面调整与数据兼容

- 电脑端解锁卡片自身位于屏幕高度中线，上方文案不再把卡片向下挤；较矮窗口使用紧凑文案布局。
- “公开净值”图的大数字显示所选区间盈亏金额。拖动日期滑块或在图内选择A、B点时，金额、颜色、涨跌幅和日期实时更新；取消A、B选择后恢复当前滑块区间。期初持仓按区间首个净值估值，计入首末日期之间的买卖费用与分红；新增投入和提取现金本身不算盈亏。未确认、失败、撤单不计入。资料不完整时显示待核验，不推算缺失字段。旁边百分比仍是所选区间的公开净值涨跌幅。
- “基金精简”内显示当前四只权益基金的持仓分布；比例以这四只基金合计为分母，四段合计100%，不计债基和自由现金流。金额沿用全局隐私开关。任一基金资料不完整时不对剩余基金重新归一化。
- 电脑端竖向菜单默认常驻正文左侧。鼠标进入正文另一侧留白时，菜单淡出后在对应侧淡入；鼠标回到正文时停留在当前侧，不隐藏。触发范围覆盖整段侧边留白，较窄窗口至少保留80像素触发区，兼容触屏电脑接入鼠标。手机导航保留原布局。
- “基金精简”移除重复的“目前暂定”名单，基金名称与占比统一在持仓分布图例显示。
- 债基六列表格已完整填写的记录按表格登记并计算，不因公开净值更新滞后而被降为待补全；估值仍注明最新公开净值日期。表格未提供的确认日与净值日不额外要求填写，也不推定。未来日期与实际缺少字段的记录继续待确认。没有修改原始交易表、放宽金额核对容差或补造确认字段。
- 未确认买入金额先加到对应基金和组合市值，包含未来日期的已登记买入；已确认记录不重复加款。成本、持仓份额、收益、收益率、区间盈亏和持有期维持原计算口径。卖出、撤单、失败记录和空白草稿不加款，现金流不自动改写。
- 常驻侧边菜单加高约三成，增加菜单项高度与上下留白；保持垂直居中，并限制在窗口高度内。
- 交易展开详情移除补充交易日期说明与估值日期说明；公式调整记录的份额明确标作“估算份额”。金额包含手续费时，估算份额仍按扣费后金额除以净值计算，不把未扣费公式当作平台确认份额。未填完记录继续处理中，原始表格未改写。
- 交易表类型下拉统一为“买入、卖出、转入”。读取时“转入”及兼容写法“转换转入”映射为transfer-in，按原表份额与转入成本纳入持仓；仅更改下拉验证，不改写交易数据或公式缓存。仅因验证编辑而改变的原匹配来源哈希同步更新，已有不匹配记录不自动升级确认。
- “占总持仓比例”从基金基本信息移到持仓与收益的市值后方；债基合计持仓金额的页面标题改为“可用子弹（元）”，计算口径保持原样。

所有验证截图使用虚拟数据；真实工作簿只在内存核验，输出状态和记录数，不输出账户金额。
