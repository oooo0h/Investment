# 网页登记与同步交易记录

2026-10-21按用户要求新增。仅在本机 `node scripts/serve.mjs` 真实模式显示；演示模式、手机导航和 GitHub Pages 不提供该入口。逐功能手工步骤与自动测试命令见[项目开发与复现说明第 18 节](../项目开发与复现说明.md)。

## 入口与操作

- 电脑端侧边菜单（或宽屏顶部导航）新增矩形 `+` 按钮，文字为“同步交易记录”；有待二次核对的转换时显示红色角标。
- 三种模式：买入、卖出、转换。买入/卖出是基金与自由现金流之间的方向记录；转换是两只基金之间的记录。
- 买入填写基金、下单日期、15:00 前/后开关和买入总支出；卖出填写基金、下单日期、15:00 前/后开关和**卖出份额**；转换填写转出基金、转入基金、下单日期、15:00 前/后开关和**转出份额**。
- 转换页为左右两列基金卡片：每列滚轮上下切换基金，中间 `⇄` 点击反转转出/转入（并清空份额）；买入/卖出页为“自由现金流卡片 + 基金卡片”两列，基金卡片内填写金额或份额。模式、下单日期、15:00 开关和预计净值日位于中间栏，不再放在卡片上方。
- 本机登记窗口在卡片背后加载 `src/trade-effects.js`（Three.js 粒子、连接弧、移动光点和指针视差）；滚轮/卡片箭头切换基金或反转时触发脉冲。无 WebGL、模块加载失败或系统“减少动态”时回退为静态卡片，不影响保存；效果只读取卡片位置，不读取金额或份额。
- 打开、关闭以及模式/日期/15点/卡片切换只增删或局部替换登记弹窗，不整页 `render()`；背景页面、图表和滚动位置保持不动。
- “保存并同步”后立即写入对应基金的 `<代码>_交易记录.xlsx` 的 `交易记录` 工作表；写入前自动备份到 `临时文件/交易登记备份/`，采用临时文件加原子替换，不覆盖草稿行。
- 写入前若 Excel 正在占用文件，会提示关闭后重试；不会写入半份文件。

## 净值日期

用户于2026-10-21确认：`交易记录` 的 A 列（成交日期）写入**顺延后的净值日**，不是下单日。

- 15:00 前且下单日是交易日：净值日为当天。
- 15:00 后，或下单日不是交易日（周末/节假日）：顺延到下一个交易日。
- 交易日历当前只覆盖 2026 年和 2025-12-31，依据上交所 2026 年休市安排；未覆盖年份会拒绝登记并提示手工处理，不猜测。
- 下单日本身保存在转换记录的 `orderDate` 字段；买入/卖出下单日保存在 `fund-trade-web/local/registration-records.json`，与表格行号绑定，不含金额。页面会同时显示净值日与实际下单日。

## 买入与卖出

| 模式 | 表单填写 | 写入列 | 说明 |
|---|---|---|---|
| 买入 | 基金、下单日期、15点、买入总支出 | A 净值日、D `买入`、E 金额、F 手续费 | F 按截图档位自动计算；E 为含手续费的总支出 |
| 卖出 | 基金、下单日期、15点、卖出份额 | A 净值日、B 净值、C 份额、D `卖出`、E 到账、F 赎回费 | 按 FIFO 持有天数和当日净值计算赎回总额、费用、到账 |

买入费率（截图优惠费率）：

- `005698`：<50万 0.150%；50万～200万 0.120%；200万～500万 0.080%；≥500万 1000元。
- `270023`：<100万 0.160%；100万～500万 0.100%；500万～1000万 0.050%；≥1000万 1000元。
- `006373`：<100万 0.150%；100万～300万 0.080%；300万～500万 0.040%；≥500万 1000元。
- `016701`：<1000万 0.150%；≥1000万 1000元。
- `006663`、`004103`、`006485`：0。

申购费用按截图公式：`净申购金额 = 申购金额 ÷ (1 + 费率)`，`申购费用 = 申购金额 − 净申购金额`；固定档直接收 1000 元。份额 = `(金额 − 费用) ÷ 净值`。

卖出费率（自然日，按成交日期起算，FIFO）：

- `005698`：<7天 1.50%；7～<30天 0.75%；30～<365天 0.50%；≥365天 0。
- `270023`：<7天 1.50%；7～<365天 0.50%；365～<730天 0.30%；≥730天 0。
- `006373`：<7天 1.50%；7～<30天 0.75%；30～<180天 0.50%；≥180天 0。
- `016701`：<7天 1.50%；7～<30天 0.75%；30～<180天 0.50%；≥180天 0。
- `006663`：<7天 1.50%；≥7天 0。
- `004103`、`006485`：<7天 1.50%；7～<30天 0.10%；≥30天 0。

赎回总额 = 卖出份额 × 净值；赎回费用 = 总额 × 对应费率；到账 = 总额 − 费用。实际费用以基金公司确认结果为准。

卖出时若该净值日净值尚未公布，页面先只写 A/D/C 并标记 `awaiting`，不计入持仓与收益；净值更新后自动回填 B/E/F，转为正常记录。该回填需要主档 JSON 已有对应净值。

写入后不复制或改写公式缓存。读取器 `scripts/local-workbooks.py` 在缓存缺失时，仅对已知的六列模板公式按规则重算：

- B 列：按 A 列日期从 `全部历史净值` 精确匹配净值。
- F 列：权益基金按 `参数!B4` 费率，债基按 0；卖出留空。
- C 列：买入/转入 `(金额−手续费)÷净值`，卖出 `(金额+手续费)÷净值`，保留六位小数。

重算结果仍标记为估算，不冒充确认成交；用户用 Excel/WPS 打开并保存后，Excel 会重新写入缓存。写入会改变工作簿哈希，历史行的来源状态按既有规则降为“沿用表格的估算”，不重新声称核实。

## 转换与二次核对

转换登记时先写两行空记录：

- 转出基金：A 净值日、D `卖出`、C 转出份额；金额/净值/手续费留空。
- 转入基金：A 净值日、D `转入`；金额/份额/净值留空。

转换配对只保存在 `fund-trade-web/local/transfer-records.json`，仅含基金代码、工作簿行号、下单日、净值日、15点标记和状态，不含金额或份额。买入/卖出的下单日与净值日配对保存在 `fund-trade-web/local/registration-records.json`，同样不含金额。

状态：

1. `awaiting`：至少一端净值尚未公布。两行均显示“转换待净值”，不计入持仓、收益或汇总；不阻塞整只基金。
2. `filled`：两端净值都已公布。服务端按以下口径回填：
   - 转出到账 = 转出份额 × 转出净值 − 转出赎回费（按转出基金 FIFO 费率）
   - 转入金额（E，含费）= 转出到账
   - 转入申购补差费：补差费率 = max(0, 转入申购费率 − 转出申购费率)，按净申购公式 `转出到账 − 转出到账 ÷ (1 + 补差费率)` 计算
   - 转入份额 = (转入金额 − 转入申购补差费) ÷ 转入净值（六位小数）
   页面出现“N 笔转换待二次核对”提醒，两行仍暂不计入。
3. `reviewed`：用户对照确认单填写实际转出到账金额、实际转入金额（含费）、两端手续费和可选转入份额后，更新两行并恢复正常计入。差额 = 实际转出到账金额 − 实际转入金额，退回到自由现金流；网页询问是否把差额计入当前自由现金流，不静默修改。

实际转换可能把少量资金退回现金，所以必须以确认单为准；自动回填只是待核对草稿，不代替核对。若平台确认单只给出扣除手续费后的转入净额，请在核对页把转入手续费改为 0、转入金额改为该净额，再确认差额。

## 接口与安全

| 方法与路径 | 内容 |
|---|---|
| `POST /__local/transactions` | 新建买入、卖出或转换 |
| `GET /__local/transfers` | 转换记录与计数（不含金额） |
| `POST /__local/transfers/reconcile` | 检查待回填的卖出与转换并写入净值/金额 |
| `POST /__local/transfers/review` | 保存二次核对结果，返回差额 |

服务只监听 `127.0.0.1`；写入接口要求同源 `Origin`、JSON `Content-Type`、最大 64KB 请求体。金额只在请求、Python 子进程和内存中出现，不写入日志、不进入转换记录。Python 调用使用 `-B`，不生成 `__pycache__`。

## 边界

- 每次写入只追加或更新指定行；不删除、不重排历史行，不改工作表结构。
- 转换回填需要主档 JSON 中已有两端净值；只更新 Excel 净值表、未更新主档时不会自动回填。
- 卖出待净值的记录同样需要主档 JSON 已有对应净值才会自动回填；回填前不计入持仓、收益和汇总。
- 当前一次转换的两行共用同一个净值日；若实际确认单上的转出与转入净值日不同，请在核对后于表格中手工调整对应日期，或在后续需求中增加两端独立日期。
- 写入会丢失 openpyxl 不支持的 Excel 扩展内容；当前工作簿只有六列表、净值表和参数表，已核验冻结窗格、列宽、数据验证和数字格式保留。
- 交易日历跨年需补充；2027 年及以后登记会被拒绝，直到补入新的休市安排。
